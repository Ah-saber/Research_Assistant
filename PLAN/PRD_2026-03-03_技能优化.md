## 所有技能详细分析

### Reading 类 (4个)

#### 1. paper-search

**当前实现流程**:
```
用户输入 → 分析查询类型 → 多策略搜索(语义→关键词→标题) → 结果展示
```

**准确性瓶颈**:
- 多策略降级可能导致结果不一致
- 无结果时用户需要手动尝试替代方案
- 未搜索本地 Obsidian 笔记

**用户体验问题**:
- 多次确认可能影响流畅度
- 多同名论文选择界面清晰但需要额外交互

**obsidian-cli 整合机会**:
| 命令 | 用途 | 效果 |
|------|------|------|
| `obsidian search` | 补充搜索本地笔记 | Zotero 无结果时搜索已有笔记 |

**描述优化建议**:
- 添加触发词："找文献"、"文献搜索"、"搜索相关论文"、"查论文"

---

#### 2. paper-summary

**当前实现流程**:
```
获取元数据 → Abstract-First策略 → 生成摘要 → 质量标注
```

**准确性瓶颈**:
- Abstract-First 质量有限（摘要省略细节）
- 全文可能超 token 限制
- 降级策略已存在但可能需要更明确的提示

**用户体验问题**:
- 质量标注需要更显眼
- 摘要不足时提示不够明显

**obsidian-cli 整合机会**:
- 无（主要依赖 Zotero MCP）

**描述优化建议**:
- 添加触发词："总结论文"、"论文摘要"、"概括内容"、"论文概要"、"总结"

---

#### 3. annotation-extract

**当前实现流程**:
```
获取item_key → 提取注释 → 按颜色分组 → 格式化输出
```

**准确性瓶颈**:
- 必须指定 item_key（已做限制）
- 空注释处理已优化
- limit 参数防止超限

**用户体验问题**:
- 空注释时建议友好
- 需要用户提供 item_key 可能不够直观

**obsidian-cli 整合机会**:
- 无（专门处理 Zotero 注释）

**描述优化建议**:
- 添加触发词："提取注释"、"导出高亮"、"PDF注释"、"提取标注"、"查看笔记"

---

#### 4. paper-notes

**当前实现流程**:
```
获取元数据 → 检查现有笔记 → Abstract-First → 创建笔记 → 建立链接
```

**准确性瓶颈**:
- Abstract-First 质量有限
- 重复检测基于 Glob 模式匹配（可能漏掉）
- 链接创建基于关键词匹配，无语义理解

**用户体验问题**:
- 重复笔记检测需要更智能
- 链接创建可能不够精确

**obsidian-cli 整合机会**:
| 命令 | 用途 | 效果 |
|------|------|------|
| `obsidian search` | 检查重复笔记 | 更精确的重复检测 |
| `obsidian backlinks` | 查找引用此论文的笔记 | 建立反向链接 |

**描述优化建议**:
- 添加触发词："创建论文笔记"、"论文笔记"、"记笔记"、"写笔记"

### Notes 类 (5个)

#### 5. note-analyze

**当前实现流程**:
```
Glob扫描 → 读取内容 → 结构分析 → 语义分析 → 生成报告
```

**准确性瓶颈**:
- 仅使用关键词共现分析，无法识别同义概念
- 整篇笔记作为文本块处理，丢失段落结构
- 主题聚类算法不明确
- **缺失：无法发现现有引用关系**

**用户体验问题**:
- 分析报告可能过于冗长
- 孤立笔记检测依赖关键词匹配

**obsidian-cli 整合机会**:
| 命令 | 用途 | 效果 |
|------|------|------|
| `obsidian backlinks` | 发现现有连接关系 | 新增能力，Glob无法实现 |
| `obsidian search` | 快速筛选相关笔记 | 减少无效Read |

**描述优化建议**:
- 添加触发词："分析笔记"、"笔记结构分析"、"检查笔记状态"、"发现孤立笔记"、"检测重复内容"、"笔记健康检查"

---

#### 6. note-organize

**当前实现流程**:
```
分析结果 → 用户确认 → 标签规范化 → 建立链接 → 合并重复 → 创建索引
```

**准确性瓶颈**:
- 依赖 note-analyze 的结果
- 索引笔记必须使用表格（已强制）
- 合并重复笔记需要用户确认

**用户体验问题**:
- 需要用户多次确认（破坏性操作保护）
- 索引笔记表格格式正确性依赖模板

**obsidian-cli 整合机会**:
- 无（主要依赖 note-analyze）

**描述优化建议**:
- 添加触发词："整理笔记"、"笔记分类"、"标签规范化"、"重组笔记"、"优化笔记结构"

---

#### 7. note-link

**当前实现流程**:
```
目标笔记 → 提取关键词 → Glob搜索 → 计算关联度 → 用户选择 → 创建链接 → 验证
```

**准确性瓶颈**:
- 关联度计算过于简单（固定权重公式）
- Glob 匹配可能匹配到不相关文件
- 链接位置判断不够智能
- **缺失：无法发现哪些笔记已链接到目标（避免重复）**

**用户体验问题**:
- 需要用户手动选择链接
- 表格中的管道符转义容易遗漏

**obsidian-cli 整合机会**:
| 命令 | 用途 | 效果 |
|------|------|------|
| `obsidian backlinks` | 获取反向链接列表 | 避免重复链接（新增能力） |
| `obsidian search` | 快速筛选候选 | 减少无效Read |
| `obsidian outgoing` | 获取出链 | 发现双向关联机会 |

**描述优化建议**:
- 添加触发词："修复链接"、"断链检测"、"建立笔记关联"、"发现关联"、"链接笔记"

#### 8. note-standardize

**用户体验问题**:
- 标签推荐可能不够精确

**obsidian-cli 整合机会**:

|------|------|------|
| `obsidian tags sort=count` | 获取标签统计 | 基于实际使用推荐标签 |
| `obsidian property:get` | 获取笔记属性 | 直接读取YAML属性 |

**描述优化建议**:
- 添加触发词：强调"必须使用"、"自动触发"，添加"格式化标签"、"检查格式"、"标准化标签"

### Phase 2: obsidian-cli 整合增强准确性（P0）

**核心原则**: obsidian-cli 提供 Glob 无法获取的信息

**重要说明**: `obsidian search` 只返回文件名，仍需 Read 内容进行语义理解

#### 2.1 note-link - 整合 backlinks（最高优先级）

**当前问题**: 无法发现哪些笔记已链接到目标，可能重复创建

**整合方案**:
```python
def check_existing_links(target_note):
    existing_links = obsidian_backlinks(target_note)
    return existing_links

related_notes = find_related(target_note)
existing_links = check_existing_links(target_note)
new_candidates = [n for n in related_notes if n not in existing_links]
```

**新增功能**:
- 获取反向链接列表（新增能力）
- 避免重复创建已存在的链接
- 发现双向关联机会

#### 2.2 note-analyze - 整合 backlinks 发现连接关系

**当前问题**: 无法发现现有引用关系图

**整合方案**:
```python
def analyze_connections(notes):
    connections = {}
    for note in notes:
        connections[note] = {
            "backlinks": obsidian_backlinks(note),
            "outlinks": extract_outlinks(note)
        }
    return connections
```
